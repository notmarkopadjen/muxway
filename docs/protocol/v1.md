# Protocol v1

Everything a client needs to talk to a muxway hub. All examples use
placeholder names.

## Transport and authentication

- HTTPS only (a hub accepts plain HTTP on loopback alone, behind a proxy).
- Every client request carries `Authorization: Bearer <token>`. Tokens look
  like `mxt_` followed by 43 URL-safe characters and are issued by the hub
  owner with `muxway hub token create`.
- Clients whose network stack rewrites `Authorization` send the token in
  `X-Muxway-Token: <token>` instead. WAP 1.x phones are such clients: their
  stack knows only the Basic scheme and re-encodes a Bearer header as Basic.
  A request may carry both headers only if they hold the same token.
- Tokens never go in URLs.

## Responses

- JSON by default. Send `Accept: text/plain` for **text mode**, meant for
  small clients: no colours, tabs expanded, trailing blanks trimmed, lines
  rewrapped to `width`.
- Errors are `{"error": "<code>"}`:

| Status | Code | Meaning |
|---|---|---|
| 400 | `bad_json`, `bad_input`, `bad_parameter` | malformed request, text with control characters, unknown key, parameter out of range |
| 401 | `unauthorized` | missing, wrong, expired or revoked token (never says which) |
| 403 | `read_only` | the pane is readable but the token or the pane's mark does not allow writing |
| 404 | `not_found` | no such host or pane, **or one the token may not see** |
| 413 | `too_large` | body over 16 KiB |
| 429 | `locked_out`, `rate_limited` | 10 failed authentications from an address in 10 minutes lock it for 10 minutes; a token may make 20 requests per second |
| 503 | `host_offline` | the host's agent is not connected |

## Addresses

`<host>/<session>/<window>.<pane>`: host alias (`[a-z0-9-]{1,32}`), session
name, window index or name, pane index. Session and window names in a
request may use `[A-Za-z0-9._-]{1,64}`; a name with other characters is
reached by window index. A pane with an alias is also `<host>/@<alias>`.

## Endpoints

### `GET /v1/hosts`

Hosts the token has a read grant on, whether connected or not.

```json
{"hosts": [{"name": "alice-laptop", "online": true}]}
```

Text mode: `alice-laptop<TAB>online` per line.

### `GET /v1/panes`

Every pane the token can read, on every connected host, sorted by host,
session, window and pane.

```json
{"panes": [{
  "host": "alice-laptop", "address": "alice-laptop/work/1.0",
  "session_id": "$0", "session": "work",
  "window_id": "@1", "window_index": 1, "window": "logs",
  "window_layout": "b25d,100x30,0,0,1", "window_active": true,
  "pane_id": "%3", "pane_index": 0, "pane_active": true,
  "width": 100, "height": 30, "title": "build", "command": "bash",
  "activity": 1767225600, "mode": "write", "alias": "logs"
}]}
```

`mode` is what *this token* may do: `write` only when both the pane's mark
and the token allow it. `window_layout` is tmux's layout string for the
window. Text mode: `<address><TAB><mode><TAB><command><TAB><title>`.

### `GET /v1/hosts/{host}/tree`

One host as sessions, windows (with layout) and panes, nested:

```json
{"host": "alice-laptop", "sessions": [{"name": "work", "windows": [
  {"index": 0, "name": "editor", "layout": "...", "active": false, "panes": [ ... ]}
]}]}
```

### `GET /v1/panes/{address}`

Query: `lines` (1 to 2000, default 100), `width` (8 to 400, default 80,
text mode), `ansi=1` (JSON only: keep colour escape sequences).

```json
{"pane": { ...as in the list... }, "content": "$ make test\nok\n"}
```

Text mode returns the last `lines` lines after rewrapping. Responses carry
an `ETag`; send it back in `If-None-Match` to get `304` when nothing
changed, which keeps polling cheap on slow links.

### `POST /v1/panes/{address}/input`

Body, exactly one of:

```json
{"text": "make test"}
{"key": "Enter"}
```

- `text`: UTF-8, 1 to 4096 bytes, no control characters (C0 including
  newline and tab, DEL, C1). It is typed literally. Send `Enter` separately.
- `key`: one of `Enter`, `Tab`, `BSpace`, `Escape`, `Up`, `Down`, `Left`,
  `Right`, `PageUp`, `PageDown`, `Home`, `End`, `C-c`, `C-d`, `C-z`, `C-l`.

Answers `204` on success.

## Agent channel

For agent implementers only; clients never see it.

- `POST /v1/pair` with `{"code_id", "host", "agent_key", "proof"}` where
  `proof = base64url(HMAC-SHA256(secret, "muxway-v1-pair\0" + host + "\0" + agent_key_bytes))`.
  The answer `{"sig"}` is the hub's Ed25519 signature over
  `"muxway-v1-paired\0" + host + "\0" + agent_key_bytes`.
- `GET /v1/agent` upgrades to a WebSocket of binary messages. Handshake:
  `hello {v, nonce, eph}` from the hub; `{host, nonce, eph, sig}` from the
  agent; `{sig}` from the hub. Signatures are Ed25519 over
  SHA-256(`"muxway-v1-agent\0"` or `"muxway-v1-hub\0"`, host, `\0`, then hub
  nonce, hub ephemeral key, agent nonce, agent ephemeral key, each prefixed
  with its 4-byte big-endian length). Keys: HKDF-SHA256 over the X25519
  secret, salt = hub nonce + agent nonce, info `muxway-v1 hub to agent` and
  `muxway-v1 agent to hub`, 32 bytes each, AES-256-GCM with a 96-bit nonce
  that is a per-direction counter starting at 0.
- Then the hub sends `{"id", "op": "list" | "read" | "input", "actor",
  "pane", "lines", "ansi", "text", "key"}` and the agent answers
  `{"id", "error", "panes", "content"}` with error codes `not_exposed`,
  `read_only`, `bad_input`, `unknown_op`, `tmux_error`.

## Versioning

The path carries the version. Additions that old clients can ignore (new
fields, new endpoints) stay in v1; anything else is v2, served next to v1
for a transition period.
