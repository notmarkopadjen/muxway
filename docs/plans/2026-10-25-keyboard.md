# Feature: the keyboard: a full terminal keyboard in a window over the pane

> Status: approved by the owner on 2026-10-25 as written. Asked for as: a keyboard icon right of
> the input line, before the microphone (keyboard, mic, send, all icons),
> on web and Android, opening a window with an old-style keyboard (the
> big terminal boards with two rows of F keys, no brand) that sends each
> key to the pane as it is clicked; modern modifiers and keys too, as many
> as can be sent.

## 1. Goal

The key row and the command row cover the common keys. Programs that need
something else (`Ctrl+Alt+Del`-style chords in an editor, `Alt+F5`,
Shift+arrows to select, the numpad, `F13` to `F24`) cannot be reached
from a phone or a browser without a hardware keyboard. The keyboard sends
any key a terminal can carry, one click at a time.

Out of scope: keys a terminal cannot carry through tmux (Super/Win,
Fn, Print Screen, Scroll Lock, Pause, media keys): they are not drawn.
No auto-repeat on hold. The glasses and the feature phone.

## 2. Design

### 2.1 The input row: three icons

```
> type into alice-laptop/work/0.0_____________________ [⌨] [◉] [⏎]
```

Right of the line, in this order: **keyboard** `⌨`, **microphone** (as
now, now an icon on every hub, dim where the hub has no transcriber),
**send** `⏎` (the word *send* becomes the icon; its title says *send*).
All three are 32 px squares like the pane buttons, with a label under the
pointer. The keyboard icon is dim on a read-only pane. Web key: `K`
(free; `k` moves in the list). Android: the same three in its input row.

### 2.2 The window

A window over the pane view, not a sheet: a title bar drawn with box
characters, `┌─ keyboard ─ alice-laptop/work/0.0 ─────────[_][×]┐`,
draggable by its bar, remembered where it was left (browser storage, per
browser). It sends to the **focused** tile and its title follows the
focus. `_` folds it to its bar; `×` or `Esc` on the window closes it. The
pane stays visible and live beneath; on a phone (web or Android) the
window takes the screen's width at the bottom, and turning the phone
sideways gives the board the whole width.

### 2.3 The board

A big terminal board of the 1980s: square sharp keycaps drawn as boxes,
legends in the pixel font, the lower row of each cap's legend dim
(shifted symbol above, the key below), a lit cap glowing for an instant
on a click, with a CRT click sound off by default. Theme ink on
background like everything else, never beige. No brand, no logo badge.

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ [F13][F14][F15][F16][F17][F18][F19][F20][F21][F22][F23][F24]                             │
│ [F1 ][F2 ][F3 ][F4 ][F5 ][F6 ][F7 ][F8 ][F9 ][F10][F11][F12]                             │
│                                                                                          │
│ [Attn][Clr ]  [Esc][` ][1 ][2 ][3 ][4 ][5 ][6 ][7 ][8 ][9 ][0 ][- ][= ][  ⌫  ]  [Ins][Hom][PgU]  [Num][ / ][ * ][ - ] │
│ [EOF ][Susp]  [ ⇥  ][Q ][W ][E ][R ][T ][Y ][U ][I ][O ][P ][[ ][] ][ \  ]      [Del][End][PgD]  [ 7 ][ 8 ][ 9 ][ + ] │
│ [Kill][Word]  [Caps ][A ][S ][D ][F ][G ][H ][J ][K ][L ][; ][' ][  ⏎   ]                      [ 4 ][ 5 ][ 6 ][   ] │
│ [Home][End ]  [ ⇧ Shift ][Z ][X ][C ][V ][B ][N ][M ][, ][. ][/ ][ ⇧ Shift ]      [ ↑ ]       [ 1 ][ 2 ][ 3 ][ ⏎ ] │
│ [Rev ][Back]  [Ctrl][Alt ][          Space          ][Alt ][Ctrl]            [ ← ][ ↓ ][ → ]  [   0    ][ . ][   ] │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- **F1 to F24**: two rows, the old terminals' way. F13 to F24 are sent as
  Shift+F1 to Shift+F12, the xterm convention, which is how terminal
  programs see them; the cap's title says so.
- **Main block**: every printable ASCII key with its shifted symbol;
  Backspace, Tab, Caps Lock, Enter, both Shifts, both Ctrls, both Alts,
  Space.
- **Navigation**: Insert, Delete, Home, End, PageUp, PageDown, the arrows
  in an inverted T.
- **Numpad**: Num Lock (client-side: on, the digits; off, the navigation
  keys, as on the old boards), `/ * - + .`, Enter, 0 to 9.
- **The left column**, the old boards' command keys, each a terminal
  chord with its job as its legend: *Attn* `C-c`, *Clr* `C-l`, *EOF*
  `C-d`, *Susp* `C-z`, *Kill* `C-u`, *Word* `C-w`, *Home* `C-a`, *End*
  `C-e`, *Rev* `C-r` (history search), *Back* `BTab`.

Modifiers are **latching**, as on a phone's on-screen keyboard and the
sticky keys of the old ones: a click on Shift, Ctrl or Alt lights it for
the next key; a double click locks it until clicked again. Caps Lock is a
lock and stays in the client. The two Shifts, Ctrls and Alts act the same.
Meta is Alt (terminals have no other).

What a click sends:

- a printable key, with no modifier or only Shift / Caps: `{"text": "a"}`
  (or `A`, or the shifted symbol);
- any key with Ctrl or Alt, or a named key with any modifier:
  `{"key": "C-M-a"}`, `{"key": "S-Up"}`, `{"key": "M-S-F5"}`;
- a named key alone: `{"key": "PageUp"}` as now.

The latched modifiers clear after the key. A refusal (read-only, offline,
rate limit) shakes the cap and toasts as the key row does.

## 3. Protocol and API changes

`key` grows from a list to a grammar (protocol v1, compatible: every old
name stays and means the same):

```
key      = [ "C-" ] [ "M-" ] [ "S-" ] base        ; in this order, each once
base     = named | keypad | char
named    = Enter | Tab | BTab | BSpace | Escape | Space | Up | Down | Left
         | Right | PageUp | PageDown | Home | End | Insert | Delete | F1..F12
keypad   = KP0..KP9 | KP/ | KP* | KP- | KP+ | KP. | KPEnter
char     = one of a-z 0-9 ` - = [ ] \ ' , . /         ; lower case, unshifted
```

- `char` needs `C-` or `M-` (alone it is `text`); `S-` with a `char` is
  refused (send the shifted character as `text`).
- `;` is not a `char`: tmux reads it as a command separator (checked:
  `C-;` arrives as `C-`). With Ctrl or Alt latched the `;` cap is dim and
  says why; no raw bytes are taken from clients to make up for it.
- `F13` to `F24` are not names (tmux types `F13` as text, checked); the
  client sends `S-F1` to `S-F12`.
- Hosts list `"keys": 2` when their agent takes the grammar. An older
  hub or agent refuses the new names with `400 bad_input`; the board dims
  every key that needs the grammar there.

Example:

```http
POST /v1/panes/alice-laptop/work/0.0/input
{"key": "C-M-Delete"}
→ 204
{"key": "C-;"}
→ 400 {"error": "bad_input"}
```

## 4. Security analysis

- Still a whitelist, now a closed grammar of at most a few thousand
  names, parsed by one function in `wire` that both hub and agent call;
  the agent maps the parsed key to tmux's own name and passes it to
  `send-keys` as one argument with `--`, never the client's string.
  Nothing outside the grammar reaches tmux, so no escape sequence, no
  `;`, no tmux command can be smuggled in a key name. Unknown names are
  dangerous precisely because tmux types them as text: the grammar is the
  wall.
- A key is a write: the write grant, the input rate limit and the audit
  line (who, when, which pane, bytes) as for every input.
- The board is client code with no new endpoint; the window's position is
  the only thing stored, in the browser.
- No new dependency: the board is drawn in HTML and CSS, the click sound
  is a few samples generated in the browser.
