# Feature: links a program names (OSC 8)

> The owner noticed on 2026-10-26 that Claude Code's hyperlinks (an
> `AB#…` work item, for one) reach the browser as coloured text only.
> Asked for a plan on 2026-10-29 and approved the same day ("I approve
> osc8 plan").

## 1. Goal

A program can mark a run of text as a link with the OSC 8 sequence
(`ESC ] 8 ; params ; URI ST … ESC ] 8 ; ; ST`): the text is a label, the
address is in the sequence. Claude Code does this for work items,
pull requests and files. tmux 3.6 keeps the sequence in
`capture-pane -e`, so the hub already hands it to the clients, and both
clients drop it today: the web's escape matcher skips every OSC, the
Android `Ansi.keep` keeps SGR only. The label shows, the address is
lost.

In scope: the two clients read OSC 8 and make the label a link, with the
same rules as an address found in the text (`http` and `https` only, a
new tab or the browser, nothing sent to the host). Out of scope: `file:`
addresses (a later plan could map them to the file preview on hosts
with roots), the `id=` parameter (used to join a link split across
rows; the clients join by position instead), text mode (no links there
by design), hosts on tmux before 3.6 (nothing to read; nothing breaks).

## 2. Design

No change to the agent, the hub or the protocol. The content a client
reads with `ansi=1` carries the sequences as tmux gives them. The
feature is a parser change in each client and one more way for a mark
to arise.

**Web.** `web/src/term/sgr.ts` already matches OSC sequences; `parseLine`
now looks at the ones that start with `8;`. The part after the second
`;` is the address: a non-empty one opens a link and is kept in the
parse state as `href`, an empty one closes it. Every span pushed while a
link is open carries `href`. The state passes from row to row as the
colours do, so a link wrapped onto the next row keeps working, and the
sequence tmux repeats at a row's start is harmless. The address is
accepted only if it is at most 2048 characters, has no control
character, and `new URL()` parses it with the protocol `http:` or
`https:`; anything else (`javascript:`, `file:`, `data:`, a relative
path, garbage) opens no link and the sequence is dropped as today.

`Screen.tsx` builds marks from the row's text; it now builds them from
the spans first: a run of spans with one `href` is a link mark from its
first to its last character, and an address found in the text is used
only where no such mark is. The anchor is the one found addresses get
(`target="_blank"`, `rel="noopener noreferrer"`, the dotted underline,
the pane's colours, the hand). Since the label may say anything, the
anchor's `title` is the address, so hovering shows where it goes; a
label that is itself an address with a different destination is the
one case to worry about, and the title answers it.

**Android.** `Ansi.keep` keeps OSC 8 sequences beside SGR, `Ansi.spans`
carries `href` through the same open/close rule and the same
acceptance (`Uri.parse`, scheme `http` or `https`, 2048 characters),
and `Links` adds the spans' links before the ones found in the text.
The tap handler is the existing one. Its plan lives in the Android
repository under the same name.

## 3. Protocol and API changes

None to the contract. `docs/protocol/v1.md` gets one sentence under
`ansi=1`: the content keeps the escape sequences tmux's `capture-pane -e`
writes, colours and OSC 8 hyperlinks among them, and a client that does
not read a sequence must drop it. Compatible.

## 4. Security analysis

- Abuse: whatever runs in a pane already decides what the pane prints;
  OSC 8 adds a destination that differs from the label. A click opens a
  new tab, sends nothing to the host and runs nothing in the page: the
  anchor is a plain `<a>` with `rel="noopener noreferrer"`, under the
  page's CSP as today. The destination is shown on hover. Only `http`
  and `https` are accepted, parsed with the browser's URL parser, not a
  regular expression, so `javascript:`, `data:`, `file:`, `vbscript:`,
  a scheme hidden by whitespace or a control character, and an address
  over 2048 characters stay text.
- Authentication and authorisation: unchanged; the content is read with
  the same grant.
- Input crossing a boundary: the sequence's parameters and address, from
  the pane through tmux. The parameters are ignored. The address is
  validated as above before it becomes an attribute; it is never
  interpolated into HTML, React sets it as a property. An unterminated
  sequence ends at the row's end as the matcher does today.
- Logging: nothing is logged by the clients; the hub and agent are
  unchanged.
- Dependencies: none.
